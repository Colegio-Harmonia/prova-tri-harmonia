# Estratégia e Registro de Testes

## Estratégia alvo

| Nível | Objetivo | Ferramenta/abordagem | Momento |
| --- | --- | --- | --- |
| Estático | detectar erro de estilo e tipo | ESLint e `tsc --noEmit` | toda subtarefa |
| Build | validar App Router e bundling | `npm run build` | toda subtarefa |
| Unidade | regras de formato, adaptadores e componentes | Vitest, iniciado na Fase 11.1 | features novas com lógica isolada |
| Integração | preservar contratos de API e permissões | mocks/ambiente isolado a definir | antes de substituir uma jornada |
| E2E/manual | validar fluxo por papel | checklist autenticada em DEV; automação de interface planejada para 11.4 | toda tela migrada |
| Pós-deploy | confirmar processo, rota e logs | smoke test e observação de logs | toda entrega em DEV |

## Regras de teste manual

- Testar como professor e como coordenação/direção quando permissões diferem.
- Testar loading, retorno vazio, erro de autorização, erro de integração e sucesso.
- Para geração/correção/lançamento, usar dados de teste em DEV e registrar IDs apenas se não expuserem dados de aluno.
- Não usar resposta de produção anônima como substituto de fluxo autenticado.

## Contrato de acessibilidade

- `npm run test:accessibility-contract` confirma foco global, redução de
  movimento, filtros nomeados, navegação semântica, rótulos de campos,
  expansão de correção, estado de carregamento e tabela de status.
- A validação manual autenticada deve percorrer os roteiros da
  `docs/fase-10-acessibilidade.md` em tema claro e escuro.

## Fundação da Fase 11

- `npm run test` executa a suíte unitária Vitest; `npm run test:coverage`
  gera o resumo de cobertura sem publicar artefatos nem dados.
- `npm run test:domain` executa a fatia de regras de negócio da 11.2:
  classificação pedagógica, papéis, importação curricular e mapeamento ENEM.
- `npm run test:api-contracts` exercita handlers reais com sessão e banco
  simulados, cobrindo autorização, formato de erro e validação sem rede ou
  dados reais.
- `npm run test:regression` reúne os contratos independentes que já existiam
  para cliente HTTP, dashboard, login, IA, documentos, acessibilidade e
  gráficos. O contrato de Google Chat foi migrado para Vitest e permanece em
  `npm run test:google-chat-private`.
- O workflow `.github/workflows/quality.yml` executa em pull requests e em
  pushes para `develop` e `main`: instalação limpa, lint, TypeScript, unidade
  com cobertura, regressão, build e orçamento de performance.
- Nenhum comando da 11.1 abre conexão com banco, usa credenciais reais, chama
  IA ou publica conteúdo. Testes de integração autenticada e E2E serão
  adicionados em subtarefas próprias.
